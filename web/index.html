SlopProof

Proof, not vibes, for vulnerability reports.

Maintainers now get AI-written security reports faster than they can read them. Most are invented; some are real. Style tells you nothing. SlopProof checks every claim against the real source code, checks every reference on the live web, then tries to reproduce the bug in a sandbox.

    Pipeline
    
      
      
        
    1. Extract claims Nemotron 3.5 Lightning
          Files, functions, line numbers, quoted code, CVEs, URLs, attack surface.
      2. 
        
    2. Check the code git + fuzzy match
          The tree at the commit the reporter saw. Do the files and functions exist? Is the quoted code real or invented?
      3. 
        
    3. Find the code tree-sitter + BM25
          Splits the project into functions and ranks them against the report's own words and the identifiers it mentions.
          Works even when a report names no file or function.
      4. 
        
    4. Check the references Tavily search + extract · Nemotron 3 Super
          Does each cited CVE exist and match? Do cited pages say what the report says? Is this a known, fixed or documented issue?
      5. 
        
    5. Text screen Nemotron 3 Ultra
          One call judges the wording alone. It is a vote, never evidence: it can lower a report's priority, or let a close
          through when the evidence-based verdict also wants to close.
      6. 
        
    6. Static analysis Nemotron 3 Ultra
          Reads the real code and traces sizes, bounds and ownership to decide if the claimed condition can happen.
      7. 
        
    7. Reproduce Nemotron 3 Ultra agent · Docker sandbox
          Builds the project with AddressSanitizer, writes a PoC through the real attack surface, runs it with no network.
      8. 
        
    8. Verdict Nemotron 3 Ultra
          CONFIRMED only with a sandbox reproduction. Closes a report only with specific contradicting evidence.
      9. 
      
    
      
    Rules we hold ourselves to
    
      
      
        
    • Wording is never evidence. The text screen may vote, but every reason we show is a checked fact. Many real 2026 curl CVEs were found with AI tools.
      • 
        
    • Closing a real vulnerability is far worse than wasting a maintainer's minute, so doubt means PLAUSIBLE.
      • 
        
    • A PoC that is itself buggy proves nothing about the project.
